# CLAUDE.md — Rotina Mágica

Guia para quem (humano ou IA) trabalha neste repositório. Mantenha atualizado a cada ciclo.

## O que é
App de código aberto (MIT; PWA para celular) com pequenos cuidados para quem atravessa ansiedade, tristeza,
solidão, cansaço ou sobrecarga. Vivências guiadas, diário de sentimentos, jogos e ajuda rápida, sem conta nem nuvem.
É autocuidado, não psicoterapia, diagnóstico ou promessa de tratar uma condição. O nome e a identidade visual seguem Rotina Mágica.

Novas instalações usam `supportFocus: general`. Quem já concluiu o primeiro uso, sem essa configuração, conserva
`recovery`, com as ferramentas anteriores para hábitos e uso de substâncias. A troca é explícita em Ajustes e não
apaga dados. O diário geral usa humor/estresse/notas dos check-ins; não converta fissura ou uso antigos em mal-estar.
O catálogo geral tem IDs próprios e usa voz do aparelho quando disponível; não reutilize áudios com roteiros antigos.
Guia da proposta e transição: `docs/proposta-acolhimento.md`. Visão histórica e evidências: `docs/visao-produto.md`.

## Critério de decisão
"Isso ajuda alguém a atravessar um momento difícil, com base clara e sem prometer tratamento?" Se a evidência é
fraca, a mudança precisa ser simples, opcional e não pode atrapalhar o acesso a uma pausa.

## Arquitetura
```
index.html, src/main.tsx   entrada; registra o service worker (só em produção)
src/App.tsx, src/router.ts navegação por hash + TabBar: '' (Hoje), #sos (Ajuda agora), #diario, #ajustes, #rotina/<passo>, #pensamento, #jogos[/id], #usei[/entender], #treino[/id], #lab, #sons, #ajustes, #primeiro-uso
src/domain/routine.ts      a rotina (Manhã/Tarde/Noite), práticas guiadas (fases com tempo), compromisso padrão
src/domain/thinking.ts     armadilhas do pensamento (TCC), dicas do corpo, contagem
src/domain/forecast.ts     Clima de hoje: previsão de risco com os dados do aparelho
src/domain/challenges.ts   Desafio da semana: metas de prática contadas com os registros
src/domain/binaural.ts     Sons para relaxar: faixas binaurais (alfa, teta, delta) e a descida da pulsação
src/domain/narration.ts    narração além das práticas: avisos curtos (cues/) e passos das vivências (training/)
src/domain/training.ts     exercícios (técnicas em passos); therapies.ts agrupa por terapia, com a base de cada uma
src/domain/games/          motores puros dos jogos (blocos, mahjong=Pares, memory=Arcanos, symbols=planetas/signos/Árvore/tarô, wave=Segura a onda, story=A noite) e rng com semente
src/features/<x>/          telas, componentes e testes de cada funcionalidade (routine/PracticeScene.tsx = cenas das práticas)
src/domain/                regras puras (sem React, sem armazenamento), 100% testável
src/data/                  repositories/types.ts (interfaces), repositories/local.ts (localStorage),
                           provider.tsx (contexto useData), test-repos.ts (repositórios em memória p/ testes)
src/platform/crypto.ts     PIN (PBKDF2) e cifra do backup (AES-GCM), via Web Crypto
src/data/backup.ts, demo.ts backup com senha; dados de exemplo do modo ?demo
src/ui/                    estilos (styles.css, tema noite e claro por variáveis), ilustrações (illustrations.tsx), ícones (app-icons.ts + Icon em icons.tsx) e componentes compartilhados (Setting = ajuste que abre e fecha)
src/platform/install.ts    botão Instalar (guarda o beforeinstallprompt do Chrome); voice.ts = voz das práticas; ambient.ts = som de fundo; binaural.ts = sons binaurais; narrated-audio.ts = MP3 gravado, se existir
public/                    manifest.webmanifest, sw.js (offline), ícones, illustrations/ (SVGs do primeiro uso e do Laboratório vazio, via `import.meta.env.BASE_URL`)
.github/workflows/         ci.yml (PR), pages.yml (publica a cada push na main) e narracao.yml (gera a narração Azure, à mão); .github/dependabot.yml (mensal)
docs/                      visao-produto.md, integracoes.md (regras para serviços externos), roteiro-narracao.md, apoio-financeiro.md, student-pack.md, img/ do README
.devcontainer/, .github/copilot-instructions.md   Codespaces e Copilot (Student Pack)
```
Regras:
- UI nunca mexe no `localStorage` direto; usa `useData()` (`repos` para ler, `write()` para gravar e re-renderizar).
- Toda entidade tem `id` (UUID), `createdAt`, `updatedAt` e `deletedAt` (exclusão lógica), preservando o histórico local.
- Regras de domínio (progresso, planos de noite, horários) são funções puras com testes.
- SOS: abre sem depender de dados, do primeiro uso nem do PIN (com PIN, esconde o kit). Do Android: segurar o ícone do app → "Agora" (atalho do manifest) = 2 toques.
- Dado corrompido nunca trava o app: `local.ts` guarda uma cópia e recomeça.

## Convenções
- Commits pequenos, em português, imperativo: `adiciona tela de SOS`, `corrige cálculo de dias`.
- Branches: `claude/...` para trabalho da IA; PR para `main`. Merge na `main` publica no Pages.
- Testes: Vitest + jsdom + Testing Library (`npm test`). Obrigatórios em `src/domain` e `src/data`;
  fluxos principais testados em `src/App.test.tsx`.
- Mudou a forma dos dados guardados? Mantenha leitura do formato antigo em `local.ts` (o celular já tem dados).
- Mudou arquivos do app? Suba `CACHE` em `public/sw.js` só se mudar a lista de arquivos fixos; o resto se atualiza sozinho.
- Texto do app: direto, acolhedor, sem moralismo, sem "você falhou". Nunca culpar.
- Notificações: texto discreto (não mencionar droga/recaída na tela bloqueada).
- Web não tem notificação agendada confiável offline no Android; lembretes dependem de alternativa (ver ROADMAP).

## Nunca
- Commitar dados pessoais, chaves, keystore, `.env` (já no `.gitignore`).
- Enviar dados para fora do aparelho (analytics, crash reporting) sem decisão explícita registrada aqui.

## Como rodar
No celular: abrir o link do GitHub Pages no Chrome → menu ⋮ → "Adicionar à tela inicial" (ou "Instalar app").

No PC (Node.js 22 LTS):
```bash
npm install
npm run dev             # abre em http://localhost:5173 (e no IP da rede, para testar no celular)
npm test                # testes
npm run typecheck       # TypeScript
npm run build           # gera dist/ (o que vai para o Pages)
```

### GitHub Pages
- Workflow `pages.yml` publica a cada push na `main`. Em Settings → Pages, Source deve ser "GitHub Actions".
- Repositório privado com Pages exige GitHub Pro (vem no Student Pack). O site fica público, mas é só o app:
  os dados de cada pessoa ficam no próprio celular. `noindex` evita buscadores.
